# Безопасность

## Пароли и сессии

- Пароли хранятся только как `scrypt`-хеш (соль + 64 байта); сравнение —
  `timingSafeEqual`. В логах и ответах пароль не появляется.
- Сессии — случайные 32-байтовые токены со сроком 30 дней. Активность
  продлевает сессию, просроченные чистятся.
- «Кик» и блокировка разрывают сессии; смена пароля завершает сессии на других
  устройствах; есть «выйти на всех устройствах».
- Администратор один, защищён от удаления, блокировки и дублирования.
  Ожидающие и заблокированные не получают доступ к данным.

## Ограничение частоты

| Эндпоинты | Лимит |
| --- | --- |
| `/api/auth/login`, `/api/auth/register` | 5 запросов/мин с IP |
| Запись состояния | 30/мин |
| Снимки и откат | 10/мин |
| Web Push | 5–10/мин на пользователя |

`trust proxy` не включается без явной настройки: иначе `X-Forwarded-For` можно
подделать и обойти лимит. За reverse proxy задайте `WAKANDA_TRUST_PROXY`.

## Заголовки и валидация

`helmet` задаёт CSP (`script-src 'self'`, без inline-скриптов в приложении),
`nosniff`, `Referrer-Policy`, запрет фреймов; в production добавляются HSTS и
`upgrade-insecure-requests`. Тело запроса ограничено (`WAKANDA_BODY_LIMIT`),
состояние сервер валидирует и нормализует — клиенту не доверяем.

Для Swagger (`/api/docs`) CSP локально мягче: UI инициализируется inline-скриптом.
Это не влияет на остальные ответы.

CORS по умолчанию выключен (только same-origin). Список доменов задаётся явно
через `WAKANDA_CORS_ORIGINS`.

## Хранение токена

Клиент хранит Bearer-токен в `localStorage` под ключом `wakanda_auth_token`
(`src/auth/AuthContext.tsx`), а состояние пользователя — в
`wakanda-state-v2:<userId>`. Причины: SPA работает без cookie-сессий и может
стартовать офлайн, а серверу не нужна куки-привязка к домену.

Риск: при успешном XSS злоумышленник сможет прочитать `localStorage` и
использовать токен до его отзыва. Митигации:

- CSP запрещает сторонние и inline-скрипты;
- React экранирует данные, а все формы проходят zod-валидацию;
- нет сторонних скриптов и трекеров;
- только HTTPS, сессии можно отозвать («выйти на всех устройствах», «кик»).

Альтернатива — cookie с `HttpOnly`, но тогда придётся отказаться от простого
same-origin SPA и добавить CSRF-защиту. Для текущей модели self-hosted это
неоправданно.

## Секреты

Токены, пароли, заголовки `Authorization`/`Cookie` вырезаются из логгера.
Публичные health/debug-поля не отдают SQL-ошибки, `chat_id` и внутренние детали.
`.env` не коммитится; в CI секреты не нужны.
